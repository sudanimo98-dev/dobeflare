Data Model

Table Schema

Two tables joined across the investigation: fraud queue signals from the Trust & Safety team, and payment transaction records from the payments team.

event_idVARCHAR(20)

Join key: event_id links fraud signals to their payment activity. organizer_id is used in Step 2 to roll up across connected accounts.
Collusion signal: When attendee_id = organizer_id, money is moving in a circle — the organizer is buying their own tickets.
Chargeback window: chargeback_eligible = FALSE means the transaction is past the 14-day bank window — the funds are unrecoverable.
Step 1

Identify the Nigerian IP Cluster

Join fraud queue signals with payment transactions to surface all events with Nigerian IP origins above risk threshold, with their full dollar exposure split by recoverability.

event_cluster_exposure.sql 
-- Step 1: Identify the Nigerian IP cluster in the fraud queue
SELECT
    fq.event_id,
    fq.organizer_id,
    fq.risk_score,
    fq.flag_date,
    fq.flag_reason,
    COUNT(pt.transaction_id)              AS total_transactions,
    SUM(pt.amount_usd)                    AS total_exposure_usd,
    SUM(CASE WHEN pt.chargeback_eligible = FALSE
             THEN pt.amount_usd ELSE 0 END) AS past_window_usd,
    COUNT(DISTINCT pt.attendee_id)        AS unique_attendees,
    -- Collusion signal: attendee buying their own tickets
    COUNT(DISTINCT CASE
        WHEN pt.attendee_id = pt.organizer_id
        THEN pt.attendee_id END)            AS self_purchase_count

FROM fraud_queue fq
JOIN payments_transactions pt
    ON fq.event_id = pt.event_id

WHERE
    fq.ip_country = 'Nigeria'
    AND fq.risk_score >= 0.80

GROUP BY
    fq.event_id,
    fq.organizer_id,
    fq.risk_score,
    fq.flag_date,
    fq.flag_reason

ORDER BY
    past_window_usd DESC;
WHERE filters: ip_country = 'Nigeria' scopes to the cluster; risk_score >= 0.80 keeps only high-confidence flags — reduces noise from borderline cases.
CASE WHEN for recoverability: Splits total exposure into recoverable vs. past the chargeback window. This was the number that mattered — $800K past the window.
self_purchase_count: A DISTINCT CASE pattern — counts distinct attendee IDs only where they match the organizer ID. Flags the circular money movement without a subquery.
Step 2

Organizer Network Rollup

Roll up to organizer level to see connected account networks — one bad actor running multiple events shows up here as a single row with aggregated exposure.

organizer_network_rollup.sql 
-- Step 2: Roll up to organizer level to surface connected account networks
SELECT
    organizer_id,
    COUNT(DISTINCT event_id)             AS events_flagged,
    SUM(total_exposure_usd)               AS total_exposure_usd,
    SUM(past_window_usd)                  AS unrecoverable_usd,
    AVG(risk_score)                       AS avg_risk_score,
    MAX(flag_date)                        AS most_recent_flag

FROM (
    -- Subquery reuses Step 1 logic
    SELECT
        fq.event_id,
        fq.organizer_id,
        fq.risk_score,
        fq.flag_date,
        SUM(pt.amount_usd)                  AS total_exposure_usd,
        SUM(CASE WHEN pt.chargeback_eligible = FALSE
                 THEN pt.amount_usd ELSE 0 END) AS past_window_usd
    FROM fraud_queue fq
    JOIN payments_transactions pt
        ON fq.event_id = pt.event_id
    WHERE fq.ip_country = 'Nigeria'
      AND fq.risk_score >= 0.80
    GROUP BY fq.event_id, fq.organizer_id, fq.risk_score, fq.flag_date
) organizer_summary

GROUP BY organizer_id
HAVING SUM(past_window_usd) > 0
ORDER BY unrecoverable_usd DESC;
Subquery pattern: Step 1's logic lives in a subquery — this avoids repeating the JOIN and WHERE, and keeps the outer query clean and readable.
HAVING clause: Filters to organizers with at least some unrecoverable exposure — removes organizers whose flagged transactions all fell within the chargeback window.
Network thinking: One organizer ID appearing across multiple event IDs is the signal for coordinated abuse — a single actor running a cluster of fraudulent events.
Investigation Result

What the Query Surfaced

The join connected fraud signals with payment reality — revealing that the money had already moved past the point of recovery.

$800K
Unrecoverable — past 14-day chargeback window
0.80+
Risk score threshold — high-confidence flags only
Nigeria
IP cluster origin — bot-created organizer accounts

The spam queue had already flagged these events for suspicious activity — bot-created accounts, Nigerian IP origins. What the join to payments data revealed was the financial picture underneath those signals: coordinated ticket purchases moving money between organizer and attendee accounts, and $800K in transactions that had already cleared.

By the time the investigation connected the two datasets, the charges were past the two-week chargeback window. The money was gone. The events and accounts were taken down, the collusion pattern was documented, and the findings became the basis for a process change: getting fraud and payments signals in front of each other earlier, so the next cluster can be stopped before the window closes.
